# Vok 目标技术架构

> 状态：2026-08-23 经用户确认。本文描述可执行目标；身份和不变量以 `.apc/manifest.md` 为准，选型根因以 `.apc/decisions.md §1` 为准。

## 1. 优先级

架构按以下顺序取舍：

1. 焦点、剪贴板、拖放和数据安全正确；
2. 呼出、输入、隐藏和交还前台可预测；
3. 长时间运行与数据增长时资源有界；
4. 模块可测试、可替换、可独立演进；
5. 在以上条件成立后优化启动时间、内存、包体和视觉。

不得以删除既定功能、虚假占位、吞错、固定延时或强制回收制造表面性能改善。

## 2. 总体结构

```text
Vok.App（WPF 表现与组合根）
          │
          ▼
Vok.Core（业务、用例、契约、纯状态机）
          │
          ▼
Vok.Infrastructure.Windows
  ├─ Win32：窗口、热键、焦点、DPI、输入
  ├─ Clipboard：监听、捕获、写回、格式规范化
  ├─ Shell/COM：快捷方式、图标、启动、OLE
  ├─ Persistence：SQLite、迁移、事务、恢复
  └─ Assets：内容寻址文件、缩略图、有界缓存
```

依赖只能向下：Infrastructure 实现 Core 契约，App 负责装配。Core 不引用 WPF、Win32、COM、SQLite 或具体日志框架。

## 3. 进程、线程与所有权

首期使用单进程，禁止先建多进程 broker。只有崩溃隔离、权限隔离或不可避免的阻塞得到实证后才重新评估。

| 所有者 | 资源 | 交接方式 |
|---|---|---|
| WPF UI STA | Window、Visual、ViewModel、托盘图标/菜单、交互式 OLE 拖放 | Dispatcher 异步接收不可变结果 |
| 热键消息线程 | 消息循环、`RegisterHotKey`、热键代次 | 发布 `HotkeyInvocation` |
| Clipboard STA | listener HWND、OpenClipboard、读写和自写水位 | 发布已复制/规范化的捕获结果 |
| Shell/COM STA | `.lnk`、Shell 元数据、图标与非交互 COM | 窄接口请求/结果 |
| Storage Executor | SQLite 写连接、迁移和事务 | 有界命令队列 |
| Image Workers | 哈希、缩略图、解码 | 有界并发和字节缓存 |

禁止后台线程读取 WPF 状态、同步等待 Dispatcher、无界队列、散落 `Task.Run` 和以毫秒 sleep 猜测系统边沿。

## 4. 工作台会话与窗口

主窗口为长期存活、`AllowsTransparency=false` 的无边框不透明普通 HWND。呼出时占满目标显示器由系统 `MONITORINFO.rcWork` 提供的工作区，保留任务栏可见且可点击；不得硬编码任务栏高度或方向。目标显示器仍按目标窗口选择，无可恢复目标时使用光标最近显示器。平台层以物理像素处理 Win32 矩形，在单一边界转换为 DIP，并响应 Per-Monitor V2 DPI 变化。

```text
Hidden → Revealing → Visible → Consuming / Dragging → Hiding → Hidden
```

每次呼出创建唯一 `GenerationId` 和 `TargetForegroundContext`。状态转换先声明所有权，再产生副作用；取消、重复输入和迟到结果必须幂等，旧代不得结束新代。

`Revealing` 期间主 HWND 仍保持普通不透明窗口，只临时使用 DWM cloak 防止未完成 surface 暴露。该 generation 的 WPF 渲染操作返回后，由单一后台 worker 执行 `DwmFlush`；同代成功才解除 cloak、请求前台/焦点，并把 content-presented 与 visible、Topmost、foreground、Win32 focus、WPF focus 一起作为进入 `Visible` 的六项门禁。watchdog 只回收永不返回的失败事务，不以超时值驱动正常显示。

进入 `Visible` 后，`Application.Deactivated` 是整个 Vok 已失去前台的唯一权威因果信号；宿主不订阅或转发单个 `Window.Deactivated`，因而主窗口切到同应用弹窗/所属窗口不会误关。应用级失活只负责按当前 generation 排队，下一 Dispatcher 轮次再次确认会话仍为 `Visible` 后，以 `ForegroundLost` 被动隐藏。此时读取真实前台 HWND 只用于诊断；即使读到 0、目标尚未稳定或捕获失败也必须隐藏。该策略完成窗口隐藏、Topmost 清理、状态机收尾和诊断发布，但保留用户刚选择的外部前台并将恢复结果记为 `NotRequested`，不得恢复呼出前旧目标。快捷键、Esc、按钮和退出仍使用恢复捕获目标的策略；它们引发的迟到应用失活由状态/generation 门禁拒绝。未来 M1 外部 OLE 拖放可在真实生命周期内增加窄范围抑制，但不得提前创建空拖放状态。

粘贴或启动的前台交接：

1. 捕获并验证目标 HWND/进程/线程；
2. 隐藏 Vok；
3. 请求恢复目标前台；
4. 观察真实前台结果；
5. 成功后才注入或完成交付；
6. 权限/UIPI 或目标失效时保留安全结果并提示，不静默失败。

`AttachThreadInput` 不是默认路径；仅允许在 `decisions.md §4` 已验证的 B 类条件下，作为具有明确连接、脱离和结果核验契约的单次窄回退。

## 5. 剪贴板流水线

```text
WM_CLIPBOARDUPDATE
  → 读取 sequence
  → Clipboard STA 有界重试并复制受支持格式
  → 规范化、内容哈希、敏感/容量规则
  → SQLite 元数据事务 + 外置资产
  → 分页投影到 UI
```

支持格式按文本、文件列表、图片逐类进入，每类单独覆盖成功、忙占用、空内容、超限、取消、自写和重复更新。不得反序列化任意对象；大图不得 Base64 进入数据库或长期驻留 ViewModel。

## 6. 存储与数据保护

- 根目录：`%LOCALAPPDATA%\Vok`；
- SQLite：元数据、排序、设置、保留策略、资产引用和 schema 版本；
- Assets：按内容哈希存放原图/缩略图，引用计数或 tombstone 清理；
- 写入：WAL、显式 ADO.NET 事务、单写者、命名 busy timeout；
- 查询：索引化 keyset 分页，不把完整历史绑定到 UI；
- 恢复：迁移前备份，损坏库/资产隔离，应用以降级状态启动，不自动销毁原证据；
- 用户文件：启动台和后续中转站只保存引用，不擅自移动、修改或删除。

隐私优先通过短默认保留期、容量上限、敏感规则、模块暂停和一键清理控制。任何“已加密”声明都必须先定义威胁模型并完成可验证实现。

## 7. 模块与通信

首期只创建 Workspace、Launcher、Clipboard、Settings。按 `decisions.md §14`，主界面可以为 Stage 与 Search 保留非交互视觉区域，但在产品里程碑批准前不得创建对应模块代码、命令、状态或伪数据。

- 应用壳层只有一个 WPF 顶层主 HWND；Settings 是主窗内部视图，托盘只发布应用命令，不拥有或旁路 Workspace 显隐事务；
- 托盘左键/菜单显示与设置请求复用代次化宿主；退出先完成宿主隐藏和 Topmost 清理，再由显式应用生命周期关闭；
- WPF 壳层使用 .NET 10 Fluent 语义资源；主题为跟随系统/浅色/深色三态，在主窗创建前加载并由专属 SQLite 执行器持久化；通知区域菜单使用 Windows 原生 `HMENU` 标准格式，不由 WPF/WinForms 自绘；
- 通知图标对象或消息 HWND 存活不代表 Explorer/Shell 仍持有登记；启动、`TaskbarCreated`、Resume、Unlock 与低频 watchdog 都以实际 HWND/GUID 调用 `Shell_NotifyIconGetRect`，缺失时在 UI STA 代次化有界重建，只有后验查询成功才完成；
- 模块拥有自己的 ViewModel、用例和生命周期取消源；
- 命令、查询、失败、取消和资源所有权走 Core 中的窄接口；
- Messenger 仅用于无需确认的广播，例如主题或数据已变化通知；
- App/主窗口不得维护跨模块“复位清单”；会话结束由模块生命周期契约驱动并可重复调用。

## 8. 性能与可靠性门禁

先建立可复测曲线，再锁定具体数值，禁止用单点任务管理器截图代替基准。

M0 至各模块都记录：

- 热键收到 → 首个稳定帧 → 输入就绪；
- 隐藏请求 → 目标前台确认 → 粘贴/启动结果；
- 启动未呼出、首次显隐后隐藏、可见稳定态的 Working Set 和 Private Bytes；
- 线程、Handle、USER/GDI 对象；
- 1000 次显隐后的增长斜率；
- 10,000 条元数据下的分页延迟和 UI 常驻项数；
- 大图峰值及离开视口后的回落；
- 数据库忙占用、损坏、资产缺失和迁移失败路径。

性能修复必须解释成本来源，并证明没有把开销转移到首次交互、错误路径或其他进程。

## 9. 发布边界

首发以 `win-x64` 自包含、非裁剪、非 Native AOT 为可验证基线。以下选项分别做 A/B：

- ReadyToRun：启动收益与包体增量；
- 单文件：解包、加载、COM 和诊断影响；
- MSIX：开机启动、升级、数据目录和 Shell 集成；
- Arm64：PInvoke ABI、Shell/OLE、图片和发布依赖；
- Native AOT/Trim：只有 WPF/XAML、COM/OLE、SQLite、全部依赖和真机交互零警告通过后才可能进入候选。

## 10. 实施阶段

### M0：生产级宿主内核

只创建解决方案骨架、普通不透明 WPF 主窗、DI 组合根、可替换热键、会话状态机、焦点捕获/恢复、Per-Monitor V2 和资源遥测。它不是一次性诊断窗口；后续模块必须直接建立在其显隐、焦点和性能契约上。不得提前实现产品模块。当前实现与验收状态见 `M0_HOST_KERNEL.md`。

状态：已于 2026-08-24 通过核心显隐、输入就绪、焦点往返和长期资源曲线验收；2026-08-27 追加 generation 级内容呈现门禁并通过真实像素回归。

### M1：启动台纵向切片

完成单条端到端闭环：拖入 → 规范化 → 持久化 → 展示/排序 → 启动 → 成败与取消。随后扩展批量、筛选和图标缓存。

状态：已完成 `decisions.md §14–§15、§17–§19` 的 Workbench 风格产品壳层与启动台纵向切片：顶部搜索预留、主体 1:2:1 的启动台/中转站/剪贴板和底部单行；启动台按动态四列卡片展示文件、目录和 `.lnk` 的持久化引用与 Shell 原图标，支持外部 FileDrop、单击反馈后安全启动、右键打开/定位/移除及内部拖动排序。外部 OLE 热路径只在 Drop 读取一次数据，窗口级多重终点与显式热键关闭抢占避免拖放租约和整区提示遗留；内部排序先内存预览、松手后单次 SQLite 事务，预览取消精确回滚。搜索与中转站仍未接入业务；剪贴板文本能力见 M2，非文件系统应用发现与图标磁盘缓存待后续切片。当前布局与交互边界见 `M1_LAUNCHER_PLAN.md`。

2026-08-27 已完成跨里程碑产品壳层增量：右上设置入口、只展示真实能力的内部设置视图、三态 Fluent 主题、Windows 原生托盘菜单和统一应用退出协调。该增量不代表 M1 启动台业务或 M3 其他可配置设置已经完成。

### M2：剪贴板纵向切片

按文本 → 文件列表 → 图片逐类完成监听、去重、保留、分页、固定/删除和向目标窗口粘贴。

状态：已于 2026-09-03 按单屏范围归档并冻结。M2.0–M2.4 的文本、文件和图片闭环、schema 6 保留/清空/资产回收、真实库迁移及单屏来源×目标矩阵均已完成；归档复验通过 Release 429/429、8/8 PowerShell AST、clipboard report v7 扩展图片矩阵 20 轮和 win-x64 自包含发布。破坏性的产品清空、物理磁盘耗尽及跨屏/多屏仍未物理验证，不属于本次完成结论。见 `M2_CLIPBOARD_PLAN.md`、`decisions.md §23–§24、§26`。

高上限演进保持现有 Clipboard 聚合、schema/CAS 所有权和 keyset 契约，不与 Stage 合并业务模型。当前产品支持上限为 10,000 条；更高档位开放前，把仓储内每次捕获后的全量保留扫描改为索引化增量维护，把 UI 已加载页累积改为有界页面窗口，并继续以独立总字节、缩略图缓存、worker 和磁盘剩余空间预算限制图片成本。这些是现有仓储/UI 边界内的实现升级，不需要推翻 Clipboard 数据模型。

### M3：中转站纵向切片

当前先以文件引用完成最小入站闭环：外部拖动中用快捷键呼出 Vok，在中转站松手后规范化、持久化并展示条目。排序/移除、点击取用和安全拖出随后独立接入；文本再后置，图片必须等模块中立的资产引用与回收边界完成后再进入。中转站与剪贴板保持独立聚合、表和生命周期，只复用经第二消费者证明的底层机制。窗口级外部 OLE 拖放必须由单一会话路由所有，不能为启动台和中转站建立互相竞争的租约。

状态：产品契约与长期路线已于 2026-09-04 锁定，按 `decisions.md §28` 收窄的拖动呼出入站 MVP 已于 2026-09-05 归档。M3.MVP1–3 已交付独立 Stage Core、schema 7、文件规范化、原子仓储、固定 64 项 VM 页面、真实 Stage WPF、唯一 `WorkspaceFileDropRouter`、数据副本门禁、独立候选和 Explorer/桌面代表矩阵；用户实际完成 5 组共 50+ 次稳定性操作，不写成计划的 100 次。文件型首期继续采用默认 50/产品上限 200 的引用容量、批量原子拒绝与重复回顶；200 不进入 schema 或仓储结构。活动外部拖动中反复显隐的源目录副本风险按用户要求延期为 `KNOWN_ISSUES.md` KI-001，源码恢复到问题报告前行为，未保留关闭抑制或 DWM/OLE Gate 实验代码，也不宣称该路径安全。下一步进入 M3.1；取用、拖出、成功消费和交付/清理双结果继续后置。见 `M3_STAGE_PLAN.md`、`M3_STAGE_MVP1_PLAN.md`、`M3_STAGE_MVP2_PLAN.md`、`M3_STAGE_MVP3_PLAN.md`、`KNOWN_ISSUES.md`、`decisions.md §26–§29`。

### M4：基础设置与数据保护

只展示已工作的快捷键、开机启动、剪贴板/中转站规则、保留策略、数据位置、隐私和模块开关。界面搜索和增强搜索继续作为后续独立纵向切片，经确认后进入。

## 11. 当前明确排除

- WebView2、Tauri、Electron 或跨平台 UI 框架；
- 全屏 layered/透明主窗口；
- 全盘常驻内存索引；
- JSON 全量在线数据库；
- 以全局 Messenger 代替服务契约；
- 未测量即采用 Native AOT、Trim、单文件、多进程或自建渲染引擎；
- 为降低指标删除功能、延迟必要工作到用户热路径或强制工作集回收。
