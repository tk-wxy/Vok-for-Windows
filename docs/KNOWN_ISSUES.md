## KI-001 活动外部拖动中反复关闭与呼出

- **状态**：延期；2026-09-05 归档，留待后续宿主/OLE 生命周期专项处理。
- **现象**：从 Explorer 发起的外部拖动仍活动时，呼出 Vok 后再次关闭会重新暴露源目录；一次测试中，带 Ctrl 修饰的拖动在源目录松开后生成了同目录 `.lnk` 副本。
- **当前基线**：按用户要求恢复到报告该问题前的 M3.MVP3 行为；不保留“拖动时禁止关闭”的临时修正、对应回归测试或 DWM/OLE Gate 探针。Stage 本身不复制、移动或删除源文件。
- **已排除方向**：关闭请求失效可避免源目录变化，但不满足交互；DWM cloak 实测 33/33 次使 OLE 命中离开目标 HWND，不能作为不可见拖放 shield。
- **后续入口**：重新处理时必须在隔离候选上同时证明“可关闭/可再次呼出、源目录零变化、OLE 终态单次、跨代隔离”；不得以固定延时、忽略 `DragLeave` 或键态猜测代替终态。
- **保留现场**：测试产生的副本属于用户文件，未经授权不删除；详细诊断报告仅保留在 Git 忽略的 `.artifacts/` 中。

## KI-002 长静置呼出仍略慢于连续热呼出

- **状态**：观察项；2026-09-14 由用户确认，不阻断 Stage P0 完成。
- **现象**：一次性初始 surface materialization 已消除明显迟缓和 Stage 白屏，但长时间静置后的第一次呼出，观感仍略慢于随后连续呼出。
- **当前证据**：受控 46 条样本中，启动预热后首次、30 秒和 5 分钟呼出的内部解除 cloak 分别约 39.9、34.0 和 52.3 ms；用户长静置实机确认核心体验达标。当前候选环形轨迹的最早长静置 session 已被后续逐项事件覆盖，不能为该次观感补写虚假精确值；保留下来的四轮解除 cloak 为 28.6–37.4 ms、输入就绪为 35.5–45.7 ms，均无 Stage 行重发、源重挂或揭示前 Availability。
- **边界**：目前没有明显卡顿、Stage 空白、失败或持续资源增长，不增加周期唤醒、固定延时、工作集锁定或 Resume 全量预热。若未来需要继续压缩冷/热差异，先取得未覆盖的同进程长静置分段轨迹与 Present 证据，再改一个机制变量。

## KI-003 长静置呼出时剪贴板图片短暂空白

- **状态**：已记录、延期；2026-09-14 用户明确本轮只记录，不纳入 Stage P0 修复。
- **现象**：长时间静置后呼出时，工作台和 Stage 已完整出现，但剪贴板栏的图片缩略图会先留空，再异步显示。
- **当前机制**：`ClipboardView` 在隐藏时取消所有 thumbnail binding、清空容器 `Image.Source` 并复位为 NotRequested；重新可见后才按已实现且位于 viewport 的容器调度加载。32 MiB cache 命中可直接复用，未命中则经单一 `_loadGate` 串行读取、校验和解码资产。Clipboard 图片当前不属于 Stage 的静态 reveal token，因此工作台不会等待这些缩略图再解除 cloak。
- **后续入口**：先区分 cache 命中、淘汰、资产读取和 UI 应用耗时，再决定首屏图片 readiness 或可复用 presentation 策略；不得通过预载全部历史、让原图进入 VM、无限扩大缓存或阻塞整个工作台来消除局部空白，并继续遵守 R23 的 viewport、revision、Recycling 和字节上限。
