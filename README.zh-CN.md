# XPC

**为 AI agent 提供可持续项目记忆的 Markdown 规范。**

XPC 是一套轻量级框架，用于让 AI 编程代理在多轮对话、跨会话、跨模型切换时，仍能保留项目上下文。它帮助代理持续记住项目目标、架构决策、常见坑点和工作约定，而不依赖运行时、守护进程、数据库或外部服务。

## 为什么需要 XPC

AI agent 在局部推理上很强，但默认是无状态的。现实中，这通常意味着它们会：

* 在不同会话之间忘记项目约束；
* 反复遇到同样的 bug 和边界情况；
* 在切换模型或工具时丢失上下文；
* 重复询问本应已经明确的事项。

XPC 的目标，就是把这些高价值知识沉淀到仓库内的一组 Markdown 文件中，让人和 agent 都能直接读取、更新和复用。

## XPC 提供什么

XPC 将项目知识拆分为几个清晰的部分：

* **项目宪法**：项目目标、技术栈、原则和不可违背的约束
* **规则**：可重复出现的坑点，以及“症状 → 规则”的长期经验
* **决策**：为何做出某个选择，以及背后的理由
* **记忆**：当前状态与最近会话中需要保留的信息
* **工作流**：agent 应该如何阅读、理解和推进项目
* **历史 / 花园**：归档或低优先级内容，不应干扰当前工作

核心思想很简单：把高价值知识保留在代码旁边，并且用 Markdown 这种人类和 agent 都容易维护的格式表达。

## 设计原则

XPC 基于三个原则设计：

1. **根目录可见**
   文件必须放在项目根目录，便于 agent 自动发现。

2. **持久知识优先于临时对话**
   长期有效的信息应该写入 Markdown，而不是只留在聊天记录中。

3. **不同内容有不同可信度**
   有些笔记是稳定且权威的，有些则是临时性的，需要在使用前确认。

## 快速开始

在新项目中初始化 XPC，只需将仓库克隆到项目根目录：

```bash
mkdir my-project
cd my-project
git clone https://github.com/tk-wxy/XPC.md.git .
rm -rf .git
git init
```

然后让你的 agent 初始化项目上下文：

> 我的项目是……请帮我初始化。

XPC 是语言无关的，适用于常见的 agent 入口文件，例如 `AGENTS.md`、`CLAUDE.md` 以及其他支持根目录指令的方式。

## 仓库结构

典型文件包括：

* `AGENTS.md` / `CLAUDE.md` / 其他类似入口文件
* `.xpc/manifest.md`
* `.xpc/rules.md`
* `.xpc/decisions.md`
* `.xpc/memory.md`
* `.xpc/workflow.md`
* `.xpc/history.md`
* `.xpc/garden.md`

最小可用配置可以先从以下几个文件开始：

* `AGENTS.md`
* `.xpc/manifest.md`
* `.xpc/rules.md`

## 适用场景

XPC 特别适合：

* 依赖 AI agent 的长期项目；
* 具有大量隐性约定的代码库；
* 反复修改且错误代价较高的项目；
* 希望把知识沉淀成结构化文档的个人或小团队工作流。

## 不太适合的场景

XPC 的价值在以下场景中相对有限：

* 一次性脚本；
* 短期实验；
* 很少使用 AI agent 的项目；
* 已经有成熟外部知识系统的团队。

## 维护方式

XPC 不会自动维护。它的价值来自于随着项目演进持续更新。

建议做法：

* 保持规则简短、稳定、可执行；
* 将过时内容归档，而不是简单删除；
* 在做出关键决策时同步记录；
* 定期清理低价值记忆。
